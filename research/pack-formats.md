## 4. era 规则：pack.mcmeta 的版本字段怎么写

以下为中文维基 [pack.mcmeta](https://zh.minecraft.wiki/w/Pack.mcmeta?action=raw) “=== 版本验证 ===”一节的规则（照抄改写，术语保持原样）：

> 由于游戏保有对旧版本的兼容性，故游戏设置了一系列对版本号的验证条件，以保证数据包或资源包若适用于旧版本则版本验证可以正常工作。在最低版本号为 2147483647 或版本验证失败时游戏会显示为“已损坏或不兼容”。
>
> 由于游戏以**游戏版本 1.21.8、数据包版本 81 或资源包版本 64** 为界使用两种格式指定版本区间，因而版本验证与数据包或资源包的适用版本不同而不同。

**A. 仅适用于 1.21.8 及之前**（数据包最高版本号低于 82，即 ≤ 81；资源包最高版本号低于 65）

* 必须指定 `pack_format` 来指定基础版本。
* 如果指定了 `supported_formats` 来指定版本区间，则必须包含 `pack_format`，且最高版本号不能低于 15。
* 不能指定 `min_format` 或 `max_format`，它们仅用于 1.21.8 后。

**B. 仅适用于 1.21.8 之后**（数据包最低版本号高于 81，即 ≥ 82；资源包最低版本号高于 64）

* 必须指定 `min_format` 和 `max_format` 来指定版本区间；二者通常为两个整数组成的数组，依次为主要版本号和次要版本号。
* 单个整数 `min_format` 被视为次要版本号 `0`（如 `94`、`[94]` 等价于 `[94, 0]`）；单个整数 `max_format` 被视为次要版本号 `0x7fffffff`。
* 不能指定 `pack_format` 或 `supported_formats`，它们仅用于 1.21.8 及之前。

**C. 同时适用于 1.21.8 前和 1.21.8 后**

上述四个字段必须同时指定，此时游戏会验证最低版本和最高版本的有效性：

* 对最低版本号的验证：`min_format` 的主要版本号和 `supported_formats` 的最小值必须相等，以保证最低版本号只有一个。
* 对最高版本号的验证，二选一：`max_format` 的主要版本号和 `supported_formats` 的最大值相等；或数据包 `supported_formats` 的最大值等于 81（资源包为 64），以保证 `supported_formats` 只在 1.21.8 及之前使用，游戏会使用 `max_format` 作为实际的最高版本号。
* `pack_format` 仍需要在版本区间内。

**叠加目录（`overlays`）** 的验证可类比推导，但与基础信息不同：即使叠加目录仅适用于 1.21.8 后，只要数据包或资源包整体适用于 1.21.8 及以前，就必须保留 `formats`，以保证旧版本游戏的文件格式验证。若任意叠加目录适用于 1.21.8 前，则应当指定 `formats`；若所有叠加目录都不适用于 1.21.8 前，不能指定 `formats`。

**中文维基给出的示例**（“数据包”页面 `{{tabber}}` 中的三个用例，字段值由 [Template:Pack.mcmeta](https://zh.minecraft.wiki/w/Template:Pack.mcmeta?action=raw) 的模板源码推导；本文件**未**渲染该模板确认缩进与换行，仅确认了字段与取值）

| 页面用例 | 模板调用 | 输出字段 |
| --- | --- | --- |
| 支持 1.21~1.21.8 版本 | `{{pack.mcmeta\|"示例数据包"\|48\|81\|type=old}}` | `"pack_format": 81`、`"supported_formats": [48, 81]`（不输出 min/max_format） |
| 支持 1.21.9~26.2 版本 | `{{pack.mcmeta\|"示例数据包"\|88.0\|107.1\|type=new}}` | `"min_format": [88, 0]`、`"max_format": [107, 1]`（不输出 pack_format/supported_formats） |
| 支持 1.21~26.2 版本 | `{{pack.mcmeta\|"示例数据包，同时支持旧版与新版格式"\|48\|107.1}}` | `"pack_format": 107`、`"supported_formats": [48, 107]`、`"min_format": 48`、`"max_format": [107, 1]` |

注意：`type=old` 分支写出的 `pack_format` 取的是**第三个参数（最高版本号 81）**，而不是最低版本号 48；第三个用例同理取 107。这是维基模板的实际行为，写 `pack.mcmeta` 时以游戏验证规则（上文 A/B/C）为准，`pack_format` 只要落在版本区间内即可。

* ✅ `pack_format` 在正式版上**单调不减**：4, 5, 6, 7, 8, 9, 10, 12, 15, 18, 26, 41, 48, 57, 61, 71, 80, 81, 88.0, 94.1, 101.1, 107.1, 121.0。

* ✅ 23 个正式版分组与 S1 的正式版表逐一比对（比对每组的首个正式版），**0 处不一致**。
* ✅ **全部 51 个正式版**的数据包版本与数据版本，用 S2（中文维基模块）与 S9（英文维基模块）逐条比对，**完全一致**；1.13–1.15.1 亦已由 S9 覆盖。
* ✅ 数据版本另用 S7（英文维基 Data version 列表）核对，未发现冲突。
* ✅ 相邻 `pack_format` 之间的跳号（如 10→12、18→26、26→41）来自只存在于快照中的中间版本号，本次不收录快照。

## 6. 不确定项 / 冲突数据

1. 愚人节版本 `2.0`（2013）在来源中只有三个颜色版本的协议版本，没有数据版本与数据包版本。
2. 愚人节版本 `15w14a` 在来源中数据版本为 `nil`（早于 15w32a），也没有数据包版本。
3. 愚人节版本 `1.RV-Pre1` 的数据版本 173 来自维基模块，但该值早于维基所说的数据版本起点 15w32a，无法用第二个来源独立确认。
4. 愚人节版本的数据包版本（24w14potato=36、22w13oneBlockAtATime=9、20w14∞=5、3D Shareware v1.34=4、26w14a=101.1）只能从同一个维基 Lua 模块确认；英文维基的 April Fools 表使用同一模块，不构成独立来源。
5. **冲突数据**：`1.21.9-pre1` 的数据版本在中文维基模块（S2）中为 **4549**，在英文维基同名模块（S9）与 Data version 页面中为 **4548**。只影响快照，不影响任何正式版。
6. `26.4` 目前只有快照（26.4-snapshot-1 = 122.0、snapshot-2 = 122.1、snapshot-3 = 123.0），尚无正式版；正式版发布后其数据包版本可能仍为 123.0 或更高。
7. 数据包版本 88.0 / 94.1 / 101.1 / 107.1 / 121.0 / 122.x / 123.0 采用“主版本.次版本”方案；JSON 数字无法保留 `.0`（`88.0` 会写成 `88`），判断主/次版本请以 `pack_format_display` 字符串为准。
8. S1 的正式版表把 101.1 那一行只写作 “26.1”，而 S2 与 S6 显示该区间覆盖 **26.1 – 26.1.2**；本文件采用后者的完整区间。
